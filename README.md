# telegram_sender

Рассылает посты (фото с карточки ВБ + подпись) во все каналы из targets.txt (интервал SEND_INTERVAL сек, порядок случайный): один раз сразу при деплое, дальше по расписанию (ofelia в docker-compose.yml).

Товаров в раздаче может быть несколько (config.py, список `ARTICLES`). Посты уходят в каналы поочерёдно:
первый канал получает первый товар, второй — второй, третий — снова первый и т.д. Так как порядок каналов
каждый раз случайный, за день каждый канал видит оба товара.

targets.txt в git не хранится: он живёт на сервере и каждый день в 23:30 МСК
пересобирается из телеграм-папки FOLDER_NAME (job update-targets). Если файла нет
(свежий клон), main.py сам выгрузит список перед рассылкой. Убрали канал из папки —
со следующего обновления он уйдёт и из рассылок.

Чаты, где правила разрешают только 1 пост в день или запрещают постить ночью, лежат в отдельной папке
FOLDER_NAME_DAILY («Раздачи 1раз»). Их список — targets_daily.txt (обновляется тем же job update-targets),
рассылка по ним — раз в день в 14:00 МСК (`main.py --daily`, job telegram-task-daily), отчёт помечен
«1 раз в день». Один и тот же чат не кладите в обе папки — он получит лишние посты. Удалили папку —
targets_daily.txt удаляется при ночном обновлении и дневная рассылка останавливается; если папки нет,
в канал отчётов приходит предупреждение вместо отчёта.

## Кэшбек из гугл-таблицы

Процент кэшбека, цена и фото подтягиваются перед каждой рассылкой из гугл-таблицы продавца
(той же, что подключена к axiomai) отдельно для каждого товара: первый лист, колонка C — процент,
колонка F — артикул, колонка G — ссылка на фото карточки, колонка K — цена. Поменяли процент или цену
в таблице — следующая рассылка уйдёт уже с новыми суммами.

Фото скачивается заново перед каждой рассылкой (photos.py): ссылка в колонке G ведёт на главное фото
карточки и не меняется, когда продавец меняет само фото. ВБ отдаёт webp, оно конвертируется в jpg
и кладётся в `photos_cache/` (на сервере в volume, в git не попадает). Не удалось скачать — берётся
фото из кэша с прошлой рассылки, нет и его — запасное `photo_<артикул>.jpg` из репозитория.

Настройки в config.py:
 - `CASHBACK_TABLE_ID` — ид таблицы (из ссылки docs.google.com/spreadsheets/d/<ид>/edit)
 - `ARTICLES` — товары раздачи: артикул, запасное фото, резервная цена и шаблон подписи у каждого свои
 - `FALLBACK_CASHBACK_PERCENT` — резервный процент, если таблица недоступна или артикул в ней не найден

Источник процента, цены и фото (таблица, кэш или резерв) по каждому товару виден в отчёте о рассылке
в REPORT_CHAT, там же публикуются сами посты.

## Файлы на сервере (в git не попадают)

 - `.env` — API_ID, API_HASH
 - `service_account.json` — ключ сервисного аккаунта Google, у которого есть доступ к таблице
 - `sender_session.session` — сессия Telegram

## При смене товара на раздачу изменить

 - запасное фото поста `photo_<артикул>.jpg`
 - config.py: запись в `ARTICLES` (nm_id, image_path, fallback_price) и шаблон подписи `CAPTION_TEMPLATE_*`.
   Ключевое слово в шаблоне у каждого товара своё, чтобы бот axiomai сразу понимал, какой товар выбрал клиент.
