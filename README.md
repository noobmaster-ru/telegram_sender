# telegram-sender — пост о «Корзина.Маркет»

Публикует одну фотографическую обложку с короткой подписью о Telegram Mini App
«Корзина.Маркет» во все каналы из `targets.txt`. Пост рассчитан на аудиторию
кэшбэк-каналов: приглашение посмотреть каталог бесплатно. С 08.10.2026 короткая
подпись заканчивается «Каталог **бесплатно**. Попробуйте👇»; «Попробуйте👇» — ссылка
на приложение. Бесплатные возможности: пять переходов к контактам и один подбор
общей корзины на аккаунт; действующая подписка снимает эти ограничения.

## Текст и настройки

Текст — `MINIAPP_CAPTION_TEMPLATE` в `config.py`. Там же ссылка `MINIAPP_URL`
(цена в подпись больше не подставляется). Ссылка ведёт в @korzina_market_bot, где Mini App
открывается кнопкой приложения. Пост отправляется одним фото с Markdown-подписью.
Обложка — `assets/korzina-market-post-cover.png`, путь — `MINIAPP_IMAGE_PATH` в `config.py`.
Она сгенерирована встроенным image_gen: иллюстративная композиция одежды и
аксессуаров, без цен и обещаний бесплатных товаров. Исходный промпт сохранён
в `assets/korzina-market-post-cover.prompt.txt`. Это не снимок конкретных товаров каталога.
Подпись ограничена 1024 символами UTF-16; отсутствие или пустой файл обложки
останавливают запуск до подключения к Telegram. Путь считается от `config.py`,
поэтому запуск из каталога с сессией работает так же, как локальный.
Фото WB, таблица Google и расчёт кэшбэка в этой рассылке не используются.
Прежние `cashback.py`, `photos.py` и товарные настройки в `config.py` оставлены
как архив и не импортируются основным скриптом.

## Команды

Запускать из папки `telegram-sender/`:

```sh
uv sync --locked
uv run python main.py --dry-run
```

`--dry-run` печатает готовую подпись и путь к обложке локально. Креды и сессия Telegram не нужны;
подключений и отправок нет.

```sh
uv run python main.py --preview
```

`--preview` отправляет пост только в `REPORT_CHAT`, не читает и не обновляет
списки каналов. Это настоящая отправка в Telegram.

```sh
uv run python main.py
uv run python main.py --daily
```

Обычный запуск делает полную рассылку. `--daily` использует отдельную папку
с лимитом один пост в день. Эти команды отправляют сообщения в Telegram.

Проверки с подменным Telegram-клиентом, без реальных сообщений:

```sh
uv run python -m unittest discover -s tests -v
```

## Каналы, отправка и отчёты

`targets.txt` и `targets_daily.txt` хранятся только локально/на сервере.
Ночной job `update-targets` в 23:30 МСК обновляет их из папок Telegram:
`FOLDER_NAME` («Раздачи бесп») и `FOLDER_NAME_DAILY` («Раздачи 1раз»).
Если списка нет, обычный запуск сначала выгружает его из соответствующей папки.
Исключения `EXCLUDED_TARGETS` применяются и при экспорте, и при отправке.

Порядок каналов случайный. Между отправками — `SEND_INTERVAL` секунд;
при FloodWait скрипт ждёт срок, указанный Telegram. Через `VERIFY_DELAY_MINUTES`
минут проверяет сохранность публикаций и отправляет отчёт с тем же фото и подписью
в `REPORT_CHAT`. Соединение закрывается и при ошибке.

Один и тот же чат не помещайте в обе папки: он получит дополнительный пост.
Расписание отдельной папки `--daily` выключено, как и в прежней версии.
Если папку удалили, ночное обновление удаляет её старый `targets_daily.txt`.

## Расписание и деплой

Основная рассылка — пять раз в день в **7:00, 12:00, 16:00, 19:00 и 21:00 МСК**
по решению владельца 05.10.2026. Расписание задано в
`docker-compose.yml`, часы для справки — `BROADCAST_HOURS` в `config.py`.
При изменении частоты обновите оба места.

Прежний GitHub Deploy sender отключён 05.10.2026 (`disabled_manually`) при
переходе на cron. Его архивный workflow перезапускал Ofelia после push в `main`.
Не включайте его одновременно с новым cron: возникнет второй планировщик.
До 08.10.2026 текущий код был перенесён на сервер напрямую. Выпуск нового текста
сохраняет эту действующую версию в Git; старый GitHub Deploy остаётся отключён.

Ручной `docker compose up app` по-прежнему отправляет уведомление о деплое
и сразу запускает полную рассылку. Не запускайте его ради проверки текста:
используйте `--dry-run`. Не запускайте два клиента с одной Telegram-сессией
одновременно.

## Локальные файлы и секреты

- `.env` — `API_ID`, `API_HASH`.
- `sender_session.session` — отдельная сессия отправителя.
- `targets.txt`, `targets_daily.txt` — списки каналов.

Эти файлы в Git не хранятся. Сессия сборщика каталога
`sadovod/catalog_session.session` для рассылки не используется.
Ключ сервисного аккаунта Google для нового поста не нужен.

## Запуск через системный cron

По поручению владельца 05.10.2026 целевой сервер — `201.51.26.53`.
Файлы установлены в `deploy/` на сервере; существующий Bot API relay сохранён,
его `/healthz` проверяется отдельно. Старый Ofelia остановлен с `restart=no`.
Cron включён после нового входа владельца 05.10.2026. Проверка авторизации
в23:55МСК успешна; в основной папке37уникальных каналов.

- Код: `/opt/telegram-sender`; зависимости Python3.13.11/Telethon1.42 —
  существующий образ, закреплённый как `telegram-sender-runtime:20261005`.
- Сессия и списки каналов: `/var/lib/telegram-sender`, рабочая папка задач.
- Логи: `/var/log/telegram-sender`, ротация — `deploy/telegram-sender.logrotate`.
- Cron запускает Docker под root; процесс Python в контейнере работает под
  UID/GID отдельного пользователя `telegram-sender`. Доступ к Docker этому
  пользователю не выдаётся. Код монтируется только для чтения, лимит памяти256МБ,
  CPU0.5; входящих портов нет.
- `deploy/run-scheduled.sh` использует одну блокировку `flock` для рассылки,
  обновления списка каналов и проверки сессии. Занятая сессия означает пропуск
  нового запуска с записью в `scheduler.log`.
- `deploy/check-session.py` проверяет авторизацию без отправки сообщений и без
  интерактивного входа по коду. Запускать через `run-scheduled.sh check-session`.

`deploy/telegram-sender.cron.utc` предназначен для `/etc/cron.d/telegram-sender`
**на сервере с системным часовым поясом UTC**: часы4/9/13/16/18UTC соответствуют
7/12/16/19/21МСК; обновление каналов20:30UTC соответствует23:30МСК. Часовой пояс
сервера нужно проверить перед установкой; переменная `TZ` внутри задачи задаёт
время логов и не меняет время запуска системного cron.

Сначала установить зависимости, защищённые `.env`/сессию и каталоги, убедиться,
что старый sender/ofelia не использует эту сессию, выполнить проверку авторизации.
Расписание включать после успешной проверки. Другой scheduler для этой же
рассылки одновременно не запускать. `cron` и Docker Ofelia — альтернативные
способы запуска одного скрипта.

На сервере подтверждены UTC/NTP, права `.env`640root:telegram-sender,
каталог сессии700telegram-sender и13Linux-проверок, включая `flock`.
Неисправный ключ сохранён в `sender_session.session.invalid-20261005`;
его нельзя использовать повторно или переносить в новую сессию.

В консоли сервера под root выполнить:

```sh
/opt/telegram-sender/deploy/login-and-enable.sh
```

Команда просит номер аккаунта, код Telegram и при необходимости пароль2FA
прямо в терминале, без записи в логи. После успешного входа проверяет аккаунт,
обновляет основную папку и лишь затем включает порученное расписание в
`/etc/cron.d/telegram-sender`. Немедленной отправки постов нет. Если вход или
подготовка каналов не удались, cron остаётся выключенным. Аккаунт должен иметь
папку «Раздачи бесп» с каналами, разрешающими публикацию.
